# 实车钢球数据与模型结果

本轮使用 `data/raw` 中 2026-07-30 采集的最终静态机械结构数据，目标仅为：

1. 判断钢球是否被识别；
2. 输出钢球球心在 640×100 水管局部校正图中的坐标。

水管轴向相对位置和物理刻度暂不处理。

## 倾斜录像微调 v4（2026-08-01）

新增样本池：

- `actual_video_frames_raw_new`：375 张，其中有球 213 张、空管 162 张；
- `actual_video_frames_raw_new_v2`：949 张，其中有球 710 张、空管 239 张。

逐图 SHA-256 检查表明第一批的 375 张图像及标签已完整包含在 v2 中，只是文件名
不同，因此两批数据的真实并集为 949 张。训练配置
[`actual_yolo11n_local_v4.yaml`](config/actual_yolo11n_local_v4.yaml) 使用旧 v3

从 `actual_yolo11n_local_v3.pt` 使用 RTX 4060 Laptop GPU 微调 30 epoch：

模型和报告：

## 水管局部校正 v3

新增 `data/raw/boundary` 后，生产坐标从“名义全图校正后的 570×80 裁剪”改为
独立的 640×100 水管局部校正图。配置见
[`config/tube_local_rectification.json`](config/tube_local_rectification.json)：

```text
参考校正平面：origin=(80,252)，output=1280×200
生产校正平面：origin=(40,126)，output=640×100
fisheye balance：0.2
```

右边界允许超过名义全图画布，从原始鱼眼帧直接 remap，因此左右物理极限球和
完整有效水管都能保留。新生成的 `actual_yolo_local_v3` 包含 834 张训练图和
387 张验证图，其中边界正样本 13 张、边界空管负样本 3 张。旧坐标标注因为焦距
和 balance 未改变，只需按两个局部原点的差值平移；所有验证标签已叠图检查。

旧 v2 NCNN 直接用于新局部图时，左极限只检出 2/5、右极限只检出 2/5；因此
完成 v3 微调并重新导出 NCNN。首次实机验证发现移除拍摄者手部背景后右侧钢球
置信度下降，因此又采集 50 张当前硬件 JPEG；Hough 复核 50/50 成功，作为仅训练
集样本重复 3 次。最终模型从 v3 只增量训练 1 轮，`lr0=1e-5`，避免过拟合当前
静止场景。

v3 PyTorch 在 387 张验证图上的训练评估指标为：

| Precision | Recall | mAP50 | mAP50-95 |
|---:|---:|---:|---:|
| 0.971 | 0.966 | 0.959 | 0.710 |

最终 NCNN 使用 `conf=0.25`：验证集 383/383 张有球图检出且 4/4 张负样本无
误报；全部边界原图左 5/5、中心 3/3、右 5/5 检出；50/50 张当前实时 JPEG
检出；全部 13 张原始空管图无误报。NCNN 在 640×100 局部图上的球心误差均值
1.00 px、P95 3.86 px、最大 7.77 px。程序只输出最高置信度候选。

验证视频标签包含旧模型辅助标注，指标主要用于检查回退，不能替代后续新增光照、
振动和独立人工标注数据。以下章节保留 v1/v2 历史结果作为基线。

正式模型与报告：

- PyTorch：`model/actual_yolo11n_local_v3.pt`；
- NCNN FP32：`model/actual_yolo11n_local_v3_ncnn_model`；
- PyTorch 验证报告：`output/actual_local_v3_full_val_report.json`；
- NCNN 生产阈值报告：`output/actual_local_v3_ncnn_val_report.json`；
- 全部边界原图报告：`output/actual_local_v3_boundary_report.json`。

最终模型已在 Raspberry Pi 5 的真实 `/snapshot` 链路上完成 130 帧验证：当前
右侧钢球 130/130 帧检出且每帧恰好一个候选，请求到结果 P95 26.80 ms，帧时间
戳到结果 P95 26.81 ms，等效约 37.3 fps，结束温度 60.9°C 且无降频。

## 旧 v1/v2 静态 ROI

配置见 [`config/actual_roi.json`](config/actual_roi.json)。

默认 `balance=0` 会裁掉最右侧钢球的一部分，因此实车识别改用：

```text
fisheye balance = 0.2
```

坐标如下：

```text
校正后 1280×720 ROI: (120, 280, 1260, 440)，大小 1140×160
生产 640×360 ROI:    ( 60, 140,  630, 220)，大小  570×80
```

该 ROI 覆盖当前全部球心位置和少量静态余量，纵向只保留水管区域。获得车辆
振动数据后必须重新检查边界，但不应直接扩大到水管外的大面积车体背景。

|---|---:|---:|

| 静态空管照片 | 7 | 3 |
| 去重视频帧 | 106 | 0 |
| 合计 | 128 | 9 |

视频共每 10 帧检查一次，268 个候选时刻中有 22 帧因运动模糊等原因未通过圆形

## 第一轮 Fine-tune

训练入口：

```bash
python train_actual.py
```

本轮从原 `best.pt` 继续训练 YOLO11n：

- `imgsz=320`、`batch=16`、60 epochs；
- 冻结前 10 层；
- AdamW，初始学习率 0.001，余弦退火；
- 禁用 mosaic、mixup、copy-paste 和水平翻转，避免生成多个钢球或不符合固定机械
  结构的图像；
- 只保留轻微平移、旋转、尺度和亮度增强。

模型：

- PyTorch：`model/actual_yolo11n_v1.pt`；
- NCNN FP32：`model/actual_yolo11n_v1_ncnn_model`。

## 结果

验证集结果：

| 模型 | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| 原 `best.pt` | 0.664 | 0.659 | 0.555 | 0.264 |
| 实车 fine-tune | 0.986 | 1.000 | 0.995 | 0.651 |

验证集只有 9 张，这些指标只能证明本轮有明显改善，不能代表最终泛化能力。

对全部 31 张静态实车图，在 `conf=0.25` 下检查导出的 NCNN 模型：

- 有球图片 21/21 检出；
- 空管图片 10/10 无误检；
- 最高置信度候选平均置信度 0.715，最低 0.593；
- 极右位置可能额外产生低置信度边缘候选，因此利用“一定有且仅有一个钢球”的
  先验，只输出最高置信度候选。
- NCNN 相对 PyTorch 的 1280×720 球心偏差平均 1.72 px、P95 3.95 px、最大
  5.38 px。

以当前人工复核球心为参考，PyTorch 模型在半尺寸 ROI 中的球心欧氏误差为：

```text
平均 1.84 px，P95 5.13 px，最大 5.97 px
```

恢复到 1280×720 坐标后约为：

```text
平均 3.68 px，P95 10.26 px，最大 11.94 px
```

这些数值衡量的是检测框中心相对当前近似人工标注的一致性，不是物理刻度误差。
精确轴向位置仍需以后使用刻度或定位装置标定。

## 第二轮动态视频数据

后续补充至 3 段 1280×720、30 fps WebM 视频，总时长约 311.9 s，共解码
9357 帧。运行：

```bash
python extract_actual_video_frames.py
```

脚本每 3 帧（0.1 s）检查一次，并根据 570×80 ROI 内球速自适应保留：

| 球速 | 最大留样间隔 |
|---|---:|
| `<20 px/s` | 1.0 s |
| `20–80 px/s` | 0.5 s |
| `80–160 px/s` | 0.25 s |
| `≥160 px/s` | 0.1 s |

球心相对上一保留帧移动 10 px 时也立即保留。Hough 与第一轮 YOLO 一致时使用
Hough 圆心；Hough 漏检时使用置信度不低于 0.25 的 YOLO 候选；两者相差超过
12 px 时使用 YOLO。仅 Hough 检出且相对前一观测跳变超过 60 px 的候选会被
拒绝。复核预览时据此排除了水管后方结构造成的错误圆形候选。

持久化结果位于 `data/actual_video_frames_v2`，包含：

- 1147 张 balance=0.2 去畸变后的 570×80 ROI PNG；
- 对应 YOLO 标签；
- 原视频、帧号、时间、估算速度、清晰度、Hough/YOLO 原始候选和最终标注；
- 全量预览和困难帧专项预览。

这些图片独立于最终训练集保存，以便以后重新分组、标注或训练。第二段完整视频
作为动态验证集，未将其相邻帧放入训练集。

## 树莓派实时链路验证

v2 NCNN 已在 Raspberry Pi 5 上使用真实摄像头链路验证：

```text
1280×720 硬件 MJPEG /snapshot
→ JPEG 1/2 IDCT 解码为 640×360
→ balance=0.2 固定 ROI remap，输出 570×80
→ actual_yolo11n_v2 NCNN FP32，2 线程，imgsz=320
→ 最高置信度球心
```

热机 130 帧结果：

- 请求取帧到识别完成：平均 26.72 ms，P95 27.78 ms；
- 原始帧时间戳到识别完成：平均 26.50 ms，P95 27.52 ms；
- NCNN 纯推理：平均 18.94 ms，P95 19.67 ms；
- 等效控制频率约 36.0 fps；
- 测试结束 70.3°C，`throttled=0x0`。

4 线程控制 P95 为 37.23 ms，长尾明显，因此当前推荐 2 线程。完整报告位于
`output/rpi_benchmark_v2`。

## 当前数据限制

- 只有一个拍摄环境，三段视频来自同一天和同一机械结构；
- 缺少不同亮度、车辆振动和受控速度；
- 动态标签主要由 Hough 和第一轮模型辅助产生，尚未逐帧人工精标；
- 精确位置和物理刻度尚未标定；
- ROI 仅验证了静止车辆，车辆运动后必须重新确认。

因此 v2 适合作为当前实车动态识别模型，但还不是最终比赛模型。
